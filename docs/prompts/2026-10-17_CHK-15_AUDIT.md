## Forks for Gary
- **F-A, placement.** (a) As written: call after the un-tick branch, before the create. A
  refused first tick still flips a Pending checklist to In Progress.
  **(b) Recommended:** move the read-only `existing` lookup above the Pending block, and
  call the resolver only when `!existing`, before the Pending write. The un-tick branch
  keeps its exact behaviour and is never refused. A refusal then writes nothing at all.
- **F-B, historic names.** (a) As written: `status: "ACTIVE"` on the single page query,
  which also blanks terminated people's names on reopened checklists.
  **(b) Recommended:** the picker query gets `status: "ACTIVE"`, plus one small org-scoped
  query for the names of staff already named in this checklist's `taskLogs`, passed to the
  client for display only (`staffById`). This also restores names for staff unassigned
  since the tick.
- **F-C, status test.** Recommended: refuse `status !== "ACTIVE"`, matching `auth.ts:215`,
  rather than `=== "TERMINATED"`.
- **F-D, a non-string id** (number, object). Today it reaches Prisma and 500s. Recommended:
  refuse it with the same generic 400 as an unknown id.
- **F-E, picker widening for hand-flagged corporate staff with no assignment.** My view:
  not now. The population is close to zero because the sync assigns them everywhere.
  Revisit if MS-4a's milestone count makes it matter.
- **F-F, calendar route parity.** `calendar/occurrences/[id]/complete` checks org only,
  with no ACTIVE or store rule. Out of scope. Candidate: COMMENT or ROW, for Gary's triage.
