## 1 · What this session is

A training lesson can point at one document from the Document Library, and only
a `kind: "Link"` document — the I-9 on uscis.gov, a state labor poster.

The case that produced it: during onboarding an employee had to fill out an I-9.
The form was already in the library as a Link with instructions and a video, but
the Day 1 lesson had no way to point at it, so the trainee had to be told to go
find it.

**Deliberately narrow.** One document per lesson, Link kind only, no new
permission surface. The narrowing is the design, not a shortcut — see §2.

## 2 · Explicitly NOT this row

- **Not Reference or any other file-backed kind.** A Reference lives in the
  private `froot-hr` blob store and is delivered only through
  `GET /api/hr/documents/[id]/download`, which asks `canReadHrDocument` before
  minting a signed URL. That function knows about library grants and knows
  nothing about lesson attachments, so serving a Reference from a lesson means a
  new tier on that route resolving lesson → module → assignment. That was the
  largest and riskiest part of the row and it serves a case already served:
  lessons already carry up to 4 uploaded files (`TrainingResource`). **A Link
  target is an external URL, so this row touches no file-delivery path at all.**
- **Not FillableForm.** HR-5 forms have no uploaded file — sentinel column values
  (`fileUrl` `""`, `contentType` `application/x-froot-form-definition`) and a JSON
  definition snapshot. There is nothing for "open" to do.
- **Not Acknowledgment.** Gary, 2026-09-05: "None of the attachment links are
  going to be acknowledgments. The acknowledgements occur when they acknowledge
  the lesson." Training's acknowledgment is `TrainingLessonProgress`; document
  acknowledgment is `HrDocumentAcknowledgment`. Two mechanisms, deliberately not
  joined here.
- **More than one document per lesson.** A lesson needing two becomes two
  lessons, or uses Files.
- **DOC-4's visibility floor.** Still awaiting its own ruling. This row must not
  preclude it — see the ruling's second sentence.
- **CSV export.** JSON export only (§6). A fourth `row_type` is its own decision.
- **`videoUrl` validation.** The lesson's existing `videoUrl` takes
  `z.string().nullish()` with no shape check and is rendered straight into an
  href. Known, ruled a COMMENT by Gary at DOC-3, deliberately untouched.

## 3 · The ruling — ratified by Gary 2026-09-05, write VERBATIM

Append to `docs/DECISIONS.md` in the file's existing style, under the heading:

`## 2026-09-05 — HR-29: linked document on a training lesson`

> Attaching a document to a lesson grants read on that document to anyone
> assigned the module, scoped to the lesson — it opens from the lesson, it does
> not appear in their document library, and it counts toward no compliance
> denominator. A lesson grant is always subordinate to a DOC-4 visibility floor:
> denial beats grant.

**Do not reword, reflow, or "clean up" this text.** It is Gary's wording and the
ratification is the wording. At commit time, print it back and ask Gary to
confirm the transcription matches before the docs commit lands.

**Why it stays in even though Link-only makes it nearly free today.** A Link's
target is an external URL, so no code currently has to consult a grant to serve
one. The ruling is the governing rule for whoever later widens this to Reference,
and the DOC-4 subordination clause has to be on the record before any code reads
it — which was Gary's stated reason for splitting DOC-4 out in the first place.

## 5 · Phase 0 — audit and plan, then STOP

Do not create or edit any source file in Phase 0. Produce a plan covering:

**5a · Schema.** `linkedHrDocumentId String?` on `TrainingLesson` with a relation
to `HrDocument`, plus the back-relation on `HrDocument`. Lean: `onDelete:
Restrict`, matching the `TrainingModule.category` precedent — documents are never
hard-deleted (DOC-1 ruling 8: hide via `isActive`, never shred), so Restrict is
inert in practice and refuses to silently orphan a lesson if that ever changes.
Confirm or argue.

Hand-authored migration per `docs/MIGRATIONS.md` (`migrate dev` is broken,
P3018). Propose the SQL — column, FK constraint, index — and say which Neon
branch it is applied to and how the branch identity will appear in the output.

**The kind invariant cannot live in the database.** `linkedHrDocumentId` must
reference a row where `kind = 'Link'`, and that is a **cross-table** condition, so
no CHECK can state it at any price — the same wall DOC-3 hit with its
zero-versions invariant, and for the same reason. It is held by the write routes
(§5b) and nowhere else. Say so in the plan and in a schema comment, so a later
session does not try to "complete" the constraint.

**5b · Write routes.** Both builder paths accept `linkedHrDocumentId` per lesson,
nullable. Validation, server-side, on **both** paths:

- resolves to an `HrDocument` in the **same organization** as the module
- `kind === "Link"`
- `isActive === true`
- anything else → 400, not a silent null

Duplicate must carry the field (it composes a full POST body client-side).
Confirm the import route is unaffected and say why.

**5c · Renderer.** A single "Linked document" block in `training-module-view.tsx`:
document title, hostname, and an Open action (`target="_blank"`,
`rel="noopener noreferrer"`, `href = externalUrl`). **Link only — do not render
the document's `instructionsHtml` or `instructionsVideoUrl` in the lesson.** The
lesson has its own body and its own video; duplicating the document's instructions
inside it is the opposite of what this row is for.

Renders in **both** modes (a manager previewing a module sees what the trainee
sees). Inactive document → renders nothing for the trainee.

**STORE never sees this block** (Gary, 2026-09-05). Lean:
**suppress at the payload level, not with a client-side conditional** — if the
field is not in the data the page hands the renderer, there is nothing to leak
and nothing for a future refactor to un-hide. Then state plainly, with
`file:line`, whether STORE can reach any of these surfaces at HEAD. If it cannot,
say that: the suppression is a guard against a widening that has been discussed,
not a live path — and the plan should not claim it was verified against a
reachable route when it was not.

**5d · Builder UI.** A select under "Video URL (optional)" in the lesson editor —
"Linked document (optional)", listing active `kind: "Link"` documents in the org.
Source the list from the server component that already loads the module rather
than adding a new API route; a new route is a new permission surface for no gain.
Empty library → a disabled option naming `/hr/documents` as where to add one.
Editing a lesson whose linked document has since been deactivated shows it with an
"(inactive)" marker rather than silently clearing it.

**5e · Gates.** `npm run build` before every commit. A staging browser check on
the `~staging` deployment as `karson@keva.com` (ADMIN): create a Link document,
attach it to a lesson, confirm Open lands on the external host, confirm preview
renders it. SQL on staging naming `br-square-feather` and the `ep-` host **in the
same output** as the row, proving the FK is populated and points at a `kind='Link'`
row. Plus the negative: a PATCH sending a non-Link document id must 400 — show it
firing, not assert it.

**5f · Staleness sweep.** Grep `docs/guide/` for any HELP-1b article covering the
training builder or the lesson editor. If one exists, adding a field to that form
makes it stale — report it, do not fix it inline (COMMENT or ROW).

**5g · Triage.** Out-of-scope findings: FIX NOW / RULING NOW / COMMENT / ROW, row
last, with counts. A RULING NOW stops the session and comes to Gary.

**STOP. Return the plan. Wait for Gary's approval before writing any file.**
