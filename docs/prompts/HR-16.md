## Why this session exists

When an employee completes every required acknowledgment on a document,
Froot mints an `HrSignedRecord` and nobody outside Froot hears about it.
HR-16 sends one email per minted record to the addresses the org has chosen:
who signed, what, which version, when, and a link to the record. This is the
first real consumer of NOTIFY-1 — real delivery proven on staging
2026-09-20 09:34 PT (Resend id `01a0bfab-3a0c-70f7-8c95-6c336460b07e`,
delivered to Gary's inbox from deployment `13bccff`).

Rulings already made (do not relitigate):
- Recipients are an org-level setting, never a hardcoded address.
- Send as `USE Froot <noreply@notify.usefroot.com>` (NOTIFY_FROM_EMAIL).
  No per-merchant sending domains.
- Env vars for the provider are NOTIFY-1's; this phase adds none.
- HR-15b: a rehire's re-sign mints a second record. That minting sends too.
- R1/R2 (DECISIONS.md, HR-8 amendments): a record minted because a signer
  completed the full current-version acknowledgment set (`recordMissing`
  → mint) is a real record. That minting sends too.

## Phase 2 — Build (only after go)

**Schema.** `Organization.hrAckRecipients String[] @default([])`. Additive
only. Generate the migration SQL with `prisma migrate diff`, write it to
`prisma/migrations/<timestamp>_hr16_ack_recipients/migration.sql`, and add
the `docs/MIGRATIONS.md` entry (additive, no rows touched, not applied by
this session). Do not apply it.

**Settings.** On the org HR settings surface from finding 4, a field
"Acknowledgment notification emails" — one or more addresses, comma or
newline separated. Zod: each entry a valid email, trimmed, deduplicated,
max 10. Role gate per F1. Save through the existing route pattern.

**Email.** New `src/lib/hr/ack-notification.ts` (or the nearest existing
lib folder for HR): one function that takes a signed-record id, loads what
the email needs, and sends via `getEmailSender()`. Plain text only:

```
Subject: Signed: <document title> v<version> — <signer name> (<store>)

<signer name on record> completed all required acknowledgments.

Document:   <title>, version <version>
Signer:     <name on record>  (executed as: <name as executed>)
Store:      <store name>
Completed:  <completedAt, UTC, full date+time>
Record:     <admin URL from finding 3>

Sent by USE Froot on behalf of <org name>. This address does not accept
replies.
```

`replyTo` is not set. Recipients = `hrAckRecipients`; F3 governs the empty
case.

**Wiring.** At the minting moment from finding 1, AFTER the record is
committed, fire the notification through Next's `after()` (the BUG-1
pattern) so a slow or failing send never delays or fails the signing
response. Wrap the send in try/catch; a failure logs (and per F2, writes
AuditLog) and never throws into the signing path. The employee's signing
must complete identically whether email is up, down, or unconfigured.

**Absolute URL.** The link needs a host. Use the existing app-URL helper if
one exists; otherwise `NEXT_PUBLIC_APP_URL` if it exists; otherwise report
in the audit which one you will need and do not invent an env var.
