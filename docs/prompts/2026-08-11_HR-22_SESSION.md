The API guard is the enforcement layer; the page gate is not.
3. **Recipient rules (R-d), each enforced SERVER-SIDE, never UI-only:**
   - ACTIVE staff only, always. Terminated is refused/excluded, never silently included.
   - Corporate staff (`isCorporate`) are EXCLUDED from entire-store expansion — Square sync expands them to every store, so a naive store expansion sweeps them in — but remain individually selectable and are included in ADMIN's everything-in-scope.
   - Every submitted staff id and store id validated against org ownership AND caller scope (`getUserStoreScope`'s derivation — PERM-6's lesson, on day one).
   - Module `isActive: true` + `isArchived: false` + applicability (`appliesTo` / store assignments) enforced server-side. The audit found the single path enforces none of these; the bulk route does not inherit that gap.
4. **The response sums to its input (CHK-3's lesson).** assigned + already-assigned + every exclusion as a NAMED count = requested, per the request and legibly per recipient. `{ created, skipped }` on the single path is the counter-example to copy *from*, not to copy: it drops org-foreign/archived ids out of its own arithmetic.
5. **Due date:** optional, no invented default (DEBT-59), applied to every created assignment, noon-normalized exactly as `staff-training.tsx:156` does it — a date must mean the same thing on both paths.
6. **Disclosure guardrail (ratified with the HR-13 call):** the confirm dialog states the immediate compliance effect plainly — "this adds N required items to compliance now" — so the pre-HR-13 dip is never a surprise even if HR-13 slips. HR-13's semantics are NOT built here.
