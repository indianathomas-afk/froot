## THE RULING THIS SESSION BUILDS TO

**R-m, ruled by Gary 2026-08-11: option (iii) — content stays, files stop.**

Once a staff member's assignment for a module is complete, that person may still read the module's lesson content through their own self-service surfaces, but **must no longer be served its attached files**. The concern being closed, in Gary's words: trade-secret material leaving the building after hours, once the training no longer requires it.

The audit established the current state, and it is not what it appeared to be:
- The only completion-aware filter is a to-do filter on the `/my` home card (`(my)/my/page.tsx:72`, `openItems.filter(i => i.status !== "complete")`) — written for a different purpose.
- `/my/training` (:17), the assignment page (:29), and the resource-download route's self tier (:60) carry **no status predicate**. Completed modules render in full with working download links.
- The only other mitigation is navigational: F7 removed Training from the tab bar while the routes stayed live. Obscurity, not a gate.

**Content types in scope (Gary, 2026-08-11):** training attachments are PDFs, images, and YouTube links — the same shape across every module.

**Known limit to state plainly, not to solve here:** a YouTube link is an external URL. Once a person has seen it, no server-side gate in this app can un-see it. This session closes what the app serves; it does not and cannot claw back external links. **The audit's own framing applies: state the limit rather than implying a guarantee the code doesn't provide.** If the plan finds that YouTube URLs are also rendered as link text in the lesson body after completion, say so and price hiding them — but do not treat hiding them as protection equivalent to the file gate.

## SCOPE

**In:**
