## SETTLED RULINGS THIS SESSION BUILDS TO

1. **Page access (R-c, ratified):** `/hr/training` stays **ADMIN-only**. HR-21 ships **no role-conditional UI** — no manager branches, no hidden-button logic. The page gate is what it is today.
2. **Colours are badge-preset KEYS** from `src/lib/badge-presets.ts` — never class strings from the DB (Tailwind 4 CSS-first constraint: a class string assembled at runtime never generates). The colour picker offers preset keys; the DB stores keys; rendering maps key → literal class.
3. **Management UI lives WITH the list it categorises** — the Manage Types dialog precedent, ruled for templates and carried here.
4. **Delete blocked while in use, with reassign offered. Rename shows the affected count first.** Follow the Manage Types dialog's exact interaction shape; if it lacks either guard, say so and propose the closest thing it does have (RULING NOW if the precedent is silent).
5. **ONE DATA SOURCE FEEDS BOTH VIEWS.** The page has one fetch and one state array today (audit §3). The list view renders from that same array — it never fetches its own data, never derives its own status/category/action set. A module must not differ between views in category, status, or available actions. **Everything this phase adds appears in BOTH views**; a feature reachable in one view and not the other is a defect, not a style choice.
6. **Toggle persistence (R-f):** `localStorage`, single key `froot.hr.training.view`. Read once on mount with a safe fallback (card view) when absent, unparseable, or storage is unavailable. No server-side preference, no user record change — extending `PATCH /api/users/me` belongs to UX-2, not here.
7. **Permissions (R-e):** new category CRUD routes use the existing inline pattern via the shared guards in `api/hr/training/access.ts` — the same tier as the module routes. Zero registry edits. PERM-5C's boundary comment untouched. HR-19 migrates this seam later.
8. **Org scoping is mandatory on every new route:** every category read, write, and delete is scoped to the caller's org via `getCurrentUser()` — never a bare id lookup (DEBT-55's class, ruled latent by R1; new code does not add to it). A category id submitted from the client is validated as org-owned before any write touches it.
